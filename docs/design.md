# ClipVault design

Build a Windows 10/11 x64 Rust clipboard history utility. A clipboard icon in the notification area opens a compact popup above or below the icon, kept inside the monitor work area. Windows controls whether the icon appears directly on the taskbar or in its overflow.

The newest 100 clipboard entries are retained, ten per page, with previous/next arrows and a page indicator. Empty pages remain navigable through page 10. Selecting an entry restores it to the clipboard, then closes the popup. Ctrl+Shift+V also opens the popup. Text is shown as a preview, images as thumbnails, and files as names. Right-click offers pause, start at sign-in, clear history, and exit. Startup is optional.

Use native Win32 APIs through windows-sys, rather than a webview or a large cross-platform renderer: this is a Windows-only tray tool and native clipboard integration is its core. A webview would add runtime requirements; a cross-platform UI would not improve the requested behavior. This is the implementer's choice under the standing authorization.

Clipboard capture preserves Unicode/plain text, HTML/RTF companions, bitmap DIB/DIBV5 and registered encoded image formats. Windows synthesizes DIB data for bitmap-only clipboard images. Image previews decode common encoded formats and DIB; the original payload remains available for restoration. Preserve all supported companion formats together. Respect Windows clipboard-history exclusion markers and password-manager confidential markers. File lists use CF_HDROP, support every extension and folders, and snapshot actual file bytes. Restore as copy rather than cut to avoid deleting originals. App-specific virtual files such as unsaved Outlook attachments must first be saved to disk; arbitrary application-private clipboard object formats are outside this release.

History is local to the Windows account, encrypted with DPAPI, and survives restart. File snapshots stream through encrypted chunks so large files do not require loading entirely into RAM. Capture/snapshot work is serialized on a worker thread. The UI stays responsive during disk work. Retry busy clipboard reads; show capture/storage failures in the popup. Only the 100 retained items and their snapshots remain in managed history. Restored file staging is retained while the corresponding entry remains, because Explorer may paste later. Eviction of the currently restored file entry first clears that clipboard reference before removing its files. This is an explicit product tradeoff for the requested strict retention cap.

Package a per-user EXE installer using Inno Setup, plus a portable EXE. Publish source and both artifacts in a public WitherBlitz/ClipVault GitHub repository, as authorized by the user. No code signing certificate is available; release binaries are unsigned. Include SHA256 checksums, build instructions, tests, CI, license, and clear support limits.

Acceptance: real clipboard round trips for Unicode text, transparent image pixels, HTML, arbitrary binary files/folders after source deletion; 101 entries evict the oldest, page boundaries are exact, encrypted persistence reopens, corrupt data is handled; tray popup/keyboard/paging observed through UI; fmt, clippy, full tests, release build, and installer smoke test pass before publication.
