# ClipVault 0.2.0 PC histories

The user requests named PC tabs immediately under the header/status text, separate histories per computer, LAN/Tailscale discovery, and automatic pairing with every ClipVault PC found on those networks. Keep automatic startup and quiet background operation from 0.1.1.

Implement native tab-like buttons with horizontal tab navigation, one local PC and discovered peers, ten pages of ten entries for the selected PC. History metadata/thumbnails refresh automatically; selecting a remote item downloads its original payload/file snapshots and restores the local Windows clipboard. Remote recalls do not become local capture entries or get re-shared. Local source histories stay capped at 100, as do per-peer fetched caches.

Native Rust Win32 UI remains. A dedicated sync service owns discovery and TLS connections; the UI never waits on networking. UDP discovery uses directed LAN broadcasts and unicast discovery to online IPv4 peers returned by an installed/logged-in Tailscale CLI. Default ports: UDP 39471, TCP 39472. Only loopback, RFC1918/link-local IPv4 and Tailscale 100.64/10 sources are accepted; no public Internet listener access or port forwarding. Tailscale ACLs and Windows Firewall still apply. Do not change security settings or accept Windows firewall UI prompts automatically.

Each installation keeps a stable self-signed TLS identity, private key encrypted by the existing account-scoped DPAPI helpers. Discovery advertises its certificate and certificate-derived ID; TLS clients trust that exact certificate, not arbitrary certificates. This encrypts transfers and pins the advertised identity, but automatic first-contact pairing does not prove ownership: any ClipVault participant on the allowed network can read the shared history. This follows the user's explicit automatic-any-PC policy and must be prominent in README and sharing status. No cloud account or relay service. Sync is enabled by default for normal runs and can be disabled persistently in the tray menu. --data-dir test instances default to sync disabled to avoid broadcasting test data; loopback tests explicitly start services with isolated ports.

Transfer metadata and files use a versioned, bounded binary protocol over TLS. Preserve full clipboard formats, source IDs, filenames and content; re-encrypt incoming payloads for the receiving account. Files stream in bounded chunks and verify length/SHA256. Reject unsafe IDs, absolute/traversal paths, malformed previews, oversized metadata, incomplete streams, stale missing items and remote failures without overwriting existing cache data. Fetch file bytes on selection rather than copying every peer's files eagerly.

Discovery/server concurrency is bounded, uses timeouts and keeps the UI responsive; there is no fixed 16-PC limit. Retain offline peer tabs with last metadata during the session, subject to stale-peer expiry for bounded discovery memory. Cache only fetched entries on disk; local histories are the only histories advertised. No automatic modification of the system clipboard when a remote history changes. The user selects a PC/item explicitly.

## Module contract

transfer.rs owns EntrySummary (id, created, title, detail, kind, preview; serde/Clone), summaries(&Store), write_entry(root:&Path,id:&str,writer:&mut impl Write)->Result<()>, and read_entry(cache_root:&Path,expected_id:&str,reader:&mut impl Read)->Result<(Record,Vec<PathBuf>)>. store.rs exposes pub(crate) protect/unprotect for identity persistence and transfer. Export reads existing encrypted payloads without opening/cleaning a Store; import is transactional and preserves source IDs, then materializes received files for clipboard restoration.

sync.rs exports start(root:PathBuf,enabled_by_default:bool)->Result<(SyncHandle,Receiver<SyncEvent>)>. SyncHandle is Clone and provides local_name()->String, publish(Vec<EntrySummary>), is_enabled()->bool, set_enabled(bool)->Result<()>, restore(peer_id:&str,entry_id:&str)->Result<(Record,Vec<PathBuf>)>. SyncEvent is Peers(Vec<PeerHistory>) or Status(String). PeerHistory has public id:String,name:String,online:bool,entries:Vec<EntrySummary>. Service owns local root, certificate/config persistence, server/discovery/polling workers and remote cache roots. UI worker publishes summaries after successful store changes and calls restore only in the background storage worker.

## Verification

Transfer roundtrips for text/image/arbitrary files and original source deletion; hostile paths/truncation/hash errors fail transactionally. Two isolated loopback sync instances discover/poll and restore text/images/files; disabled sync blocks access, wrong certificates fail, tailscale JSON parsing and allowed-address rules have tests. Native tab switching shows the selected PC's entries and correct restore command; paging remains exact. Existing 14 tests stay green. Build/lint/format, installer background-start smoke, and release download hashes remain required. Actual separate-PC LAN/Tailscale and interactive firewall/multi-monitor checks may require user machines; report that boundary without claiming they were observed.
